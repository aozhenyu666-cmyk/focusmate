## 两个真实存在的体验问题（不掩盖）

1. **ADB 输入法截断**：`adb shell input text "I finished the first part"` 只输入了 `I`。
   这不是 APP 的 bug，是 adb 空格分隔参数所致；用 `%s` 转义后正常。
   但它暴露了一个**好行为**：伙伴对只发了半个字母的回复是「你只发了个 I，是没打完吗？我等你。」
   ——没有硬猜，也没有假装听懂。

2. **测试中改了两个配置项**：
   - `quietStartMinute/quietEndMinute` 设为 0（不落在免打扰），只是为了在测试窗口内能触发；
   - 约定到期间隔用 90 秒而不是 10 分钟。
   规则本身没有关闭：禁言、频率上限、迟到判定、收尾冷却全都在生效路径上。

## 手机验收清单（约 12 分钟）

1. 装 APK → 开悬浮窗 + 无障碍（约 1 分钟）
2. 设置页填地址/模型/Key → 点「测试连接」，应显示「连接成功」（1 分钟）
3. 发一句中文（如「你好，我叫小敖」）→ 应简短回应（1 分钟）
4. 发「十分钟后问问我进度」→ 事项页应出现一条带话题与时间的约定（1 分钟）
5. 回「好的」→ 确认那条约定**还在**（不该被无关回复清掉）（30 秒）
6. 开始 5 分钟专注 → 打开抖音/YouTube，应被拦；按返回键，拦截**不该消失**（2 分钟）
7. 专注期间到约定时间 → 伙伴**不该开口**（1 分钟）
8. 到期恢复 → 之前被拦的应用应能正常打开（1 分钟）
9. 等约定主动开口 → 回复它 → 事项应转「已说过」（2 分钟）
10. 记忆页「忘掉」一条 → 再问相关话题，旧内容不该被引用（1 分钟）
11. 息屏 2 分钟再亮屏 → 专注剩余时间应连续，不重置（30 秒）
12. 杀进程重开 → 约定与记忆仍在（30 秒）
